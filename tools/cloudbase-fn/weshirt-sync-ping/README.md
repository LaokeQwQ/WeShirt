# WeShirt 同步触发器

[English](README.en.md)

用于没有常驻进程的部署环境，定时触发 WeShirt 服务端的同步检查。函数只向受保护接口发送一次 POST，不访问设备上游、不传原始设备数据，不需要上游账号或管理员口令。

## 配置

将本目录的 `index.js` 与 `package.json` 上传到 CloudBase 或支持 Node.js CommonJS 的函数平台。无需安装第三方依赖，入口为 `index.main`，平台执行超时应大于 30 秒。

在函数的环境变量中设置：

| 变量 | 值 |
| --- | --- |
| `WESHIRT_SYNC_URL` | 你的 HTTPS 站点加 `/api/cron/sync`，例如 `https://laundry.example.test/api/cron/sync` |
| `WESHIRT_SYNC_KEY` | 从 WeShirt 后台获取的专用同步密钥 |

使用同步密钥，不使用管理员口令或用户 token。密钥随服务端 `AUTH_SECRET` 派生；更换认证密钥后，应更新触发器环境变量。

同步地址必须是 HTTPS，路径为 `/api/cron/sync`，不接受查询参数、片段或 URL 内的账号密码。密钥只在 JSON 请求体 `{ "k": "..." }` 中发送，不放在 URL、日志或定时器参数中。

## 调度

在平台支持的范围内，配置每分钟触发一次或更密的调度。建议至少每分钟执行一次检查，以便提前 3 分钟和结束阶段的提醒有机会及时评估；若平台最低只能每 5 分钟调度，提前提醒可能错过窗口。设备状态与通知仍受上游响应和消息通道影响。

函数设有 30 秒总超时，不跟随 HTTP 重定向，也不会在单次执行内重试。失败后交给下一次定时触发，避免重叠触发形成请求风暴。平台如默认重试，可限制重试次数和并发。

## 结果

成功返回 `{ "ok": true, "status": 200 }`。失败返回固定原因分类、`status` 和 `eventId`：`missing_sync_key`、`invalid_sync_url`、`timeout`、`network_error`、`response_error`、`request_error` 或 `http_error`。收到服务端事件标识时沿用该标识；否则生成 `trigger_` 标识，未获得 HTTP 响应时状态为 `0`。失败执行仅记录这三个安全字段，便于查找对应调用。

函数不打印请求配置、密钥、完整 URL 或响应正文。部署验证时在后台查看同步时间是否推进、告警是否出现；不要把密钥粘贴到公开问题、截图或日志中。

此触发器解决的是定时唤醒，不改变服务端的上游出口。上游访问失败时，服务端保留最近一次完整快照并记录诊断，不会由该函数拼装或回写部分设备列表。
