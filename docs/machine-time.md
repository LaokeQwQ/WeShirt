# 设备计时、校准与自动同步

看板、我的洗衣、后台、队列和通知使用最新平台计时。登记时填写的时长只在上游缺少计时或查询失败时提供估计回退，不覆盖更新后的平台截止时间。运行状态的倒计时归零显示“即将完成”；必须收到新鲜的实际空闲状态，才确认本次运行完成。

网页与安卓前台约每30秒拉取数据。网页切回前台或恢复网络时立即刷新；安卓回到前台立即恢复同步，后台暂停页面轮询。显示时以服务端时间校正手机时钟，秒级本地插值仅用于两次平台更新之间的倒计时，不据此改变设备状态。静态资源继续缓存，实时状态不经浏览器/CDN二次陈旧缓存。

## 管理校时

机器管理提供独立校时入口，授权范围随机器管理权限。手动偏移是整数分钟，允许 −120 至 +120：正数推迟、负数提前。例如平台还剩10分钟而现场约8分钟，可先设置−2。服务端保留未校准的 `platformFinishAt`；任何再次投影均从原始值加一次偏移。

自动校时默认关闭。开启后，仅采用从空闲进入运行、持续观察至两次新鲜空闲确认的完整周期，用“实际运行时长−平台初始预计时长”取得样本。最多保留7个样本，用中位数抑制偶然误差，每个周期最多修正2分钟；手动与自动偏移相加后仍限制在±120分钟。自动学习记录可重置，手动值不受影响。

HTTP405、网络失败、故障、未看到起始过程、观察间隔超过3分钟、设备漏采样和明显修改/延长程序时丢弃本次周期。自动校时是估计修正，平台返回的实际结束状态始终优先。

## 提醒验证

钉钉、WebPush和原生通知在统一同步链路中判断阶段。临近提醒取当前剩余时间；平台延后时不会使用旧登记截止时间提前通知。完成通知独立于临近提醒，并要求真实结束依据。各阶段持久去重，重试时重新验证账号、通知偏好、占用关系和设备状态。

安卓本地计划执行前重新读取授权、任务及必要的机器状态。平台延后时重新排期；仍在运行且计时为零时等待更新。仅请求失败时可发送明确标注的估计提醒，权限拒绝、退出登录、任务已取消或转交不会继续发送。

服务端定时同步应每分钟执行，整点群播报前一分钟复核。查询失败不当作机器故障，不宣称机器空闲。
