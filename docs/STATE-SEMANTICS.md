# 机器状态与登记计时

[English](en/STATE-SEMANTICS.md) · [频道聊天](COMMUNITY.md)

## 设备类型与程序

设备类型优先采用上游类别代码：`00`/`01` 是洗衣机，`02` 是烘干机；缺少可信类别时，再依次兼容机位绑定、已有类型和名称。名称或旧机位不能覆盖明确的上游类别，客户端也不能伪造设备类型。

洗衣/自洁允许 **1–180 分钟整数**，烘干允许 **10–180 分钟整数**。常用预设只是快捷输入，不代表每栋楼设备都支持同一组程序。明确选择“桶自洁 6 分钟”才记录 `program: self_clean`；手填 6 分钟或设备恰好剩余 6 分钟不自动推断程序，也不会自动记录“已经自清洁”。

## 三种信息来源

| 信息 | 含义 |
| --- | --- |
| 上游状态及真实 `finishAt` | 设备报告的运行状态与预计结束时间；未知程序显示“程序未提供” |
| 用户登记时长 | 用户提供的预计计时，用于登记和提醒；不是硬件遥测 |
| 故障健康投影 | 根据新鲜、独立快照确认故障/恢复，保留待复核和数据过期状态 |

运行中没有真实结束时间时显示“时间未知”，不硬补 30/60 分钟，也不在估计时间耗尽时把机器改成空闲。“我的洗衣”登记计时到点只表示用户预计时段结束，是否真的洗完仍以设备新状态和现场情况为准。

若用户已登记、上游却暂时仍报空闲，界面可显示“用户已登记，等待设备状态更新”，并标注估算来源。该投影不声称硬件已启动，不能覆盖可信运行/故障或过期状态；有效登记结束或取衣后不再沿用旧投影。

故障和恢复均需要 **两份不同的新鲜快照，至少相隔 30 秒**确认。重复读取同一快照不累计次数；单份故障先显示待复核，确认故障后的单份正常数据仍显示恢复待复核。过期数据显示未知，不因刷新页面或用户报告恢复就直接宣布正常。

登记、故障/恢复等用户上报先展示机器、计时方式、时长和公开备注/标记摘要，确认后才写入。取消会保留草稿；确认期间目标或内容改变，需要重新确认。贡献者应保留这些来源区别，并覆盖缺少结束时间、6 分钟程序、上游延迟和重复快照的回归。
