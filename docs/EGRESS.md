# 同步触发与上游访问

[返回首页](../README.md) · [English](EGRESS.en.md)

WeShirt 的设备归一化、完整快照校验、故障复核和通知判定集中在服务端同步流程。前端查询复用服务端结果；定时器只负责触发该流程，避免维护多份抓取与通知逻辑。

## 运行方式

Node 服务启动后会先同步一次，再按 `server/index.js` 中的周期检查。Edge Functions 没有常驻定时器，需要平台或外部定时任务唤醒。仅靠用户访问页面触发懒刷新，不能保证用户关闭页面后继续收到提醒。

推荐使用仓库中的 [受保护同步触发器](../tools/cloudbase-fn/weshirt-sync-ping/README.md)。它仅发送：

```http
POST /api/cron/sync
Content-Type: application/json

{ "k": "<sync-key>" }
```

`WESHIRT_SYNC_URL` 配置为站点的 HTTPS 同步地址，`WESHIRT_SYNC_KEY` 使用后台提供的专用同步密钥。密钥不写入 URL 查询参数，不放进日志，不使用管理员口令代替。认证密钥轮换后，记得同步更新触发器。

## 调度与提醒

按平台支持能力，建议每分钟至少进行一次检查。提前 3 分钟提醒依赖检查落在对应时间窗口内；每 5 分钟或更长的调度可能跳过该窗口。整点群播报在北京时间允许时段的整点后 10 分钟内评估，每小时去重，机器有意义状态未变则跳过。

触发器使用 30 秒总超时，不跟随重定向，单次不自动重试。失败由下次调度再尝试；如平台有自身重试机制，应控制并发与重试次数。后台同步时间和通知通道结果是判断运行状况的依据。

## 上游失败时如何定位

先检查后台同步时间、连续失败次数和上游诊断，区分配置错误、超时、认证失败、限流与网络问题。上游状态映射、点位、请求头和账号配置以当前接口及部署环境为准，凭据只保存在服务端。

服务端对同一分区合并同步请求、限制分页并发，并在失败时保留最近一次完整快照。任意楼层或设备类别失败时，不能把其他成功组合当作完整设备列表发布。数据过期会显示待更新提示，未知数据不会累积故障确认次数。

只触发同步的函数不会改变 Edge 服务端访问上游的出口。若现有环境需要独立抓取出口，可选用 [CloudBase 抓取适配器](../tools/cloudbase-fn/weshirt-sync-ingest/README.md)，复用共用客户端获取完整快照，再交回 Edge 统一处理。不要把含真实主机地址、上游账号或原始响应的旧脚本提交到公开仓库。

## 本地验证

触发器无第三方依赖，本地测试使用模拟请求，不调用真实消息或设备接口。发布前运行根目录的 `npm test`，并检查函数环境变量已配置、后台同步时间能自动推进。不要在共享日志中打印请求体或服务端诊断正文。
